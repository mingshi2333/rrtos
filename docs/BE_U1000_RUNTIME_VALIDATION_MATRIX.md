# BE-U1000 Runtime Validation Matrix

This matrix records the staged runtime validation story for the `be_u1000` board path.

It elaborates board-stage evidence for `be_u1000`, but it does not replace the
normative support-status decisions in `docs/SUPPORTED_MATRIX.md`.

## Status labels

- `supported`: part of the default supported workflow
- `historical`: older staged SMP notes retained for context, but no longer exposed as maintained pixi tasks
- `unresolved`: explicit gap remains

## Current interpretation

- `S0` is the supported fallback behavior: both demo tasks share a single scheduler lane (`OS_CFG_CPU_COUNT=1` with `OS_SMP_EN=OFF`) and the board self-test passes.
- `E0` is the first focused SDK-port proof: it is useful for migration work, but it does not replace the maintained `S0` supported lane.
- `E1` extends that focused migration proof to button polling semantics; it also remains experimental and does not replace the maintained `S0` supported lane.
- `E2` extends the focused migration proof to UART output semantics while still staying outside the maintained `S0` supported lane.
- `E3` extends the focused migration proof to CANFD loopback semantics, but it is still limited to internal loopback/simulation and does not replace later silicon bus validation.
- `E4` extends the focused migration proof to non-destructive QSPI/flash access semantics, but it does not replace later destructive erase/write/XIP validation on real silicon.
- `E5` extends the focused migration proof to the current I2C master init/probe seam, but it does not yet prove full one-board communication or interrupt-driven parity because those remain beyond the present HAL surface.
- `E6` extends the focused migration proof to timer/timebase behavior, but it is explicitly a CLINT-backed RTOS adaptation and not proof that the BE-U1000 `TIM0` peripheral itself is already modeled or parity-complete.
- `E7` extends the focused migration proof to ADC by adding a minimal SDK-derived `hal_adc` surface, but it is still only a timeout-safe single-trigger lane and not yet proof of interrupt, DMA, calibration, or silicon-faithful ADC behavior.
- `E8` extends the focused migration proof to watchdog configuration/reload semantics, but it does not yet prove real reset behavior or full interrupt-path parity on silicon.
- `E9` extends the focused migration proof to PWMG register/config semantics plus ARR/CCR-related compare-match observation and compare-interrupt-enable lifecycle behavior, but it does not yet prove real PWM waveform timing or pin-level output on silicon.
- `E10` extends the focused migration proof to DMA channel programming semantics, but it does not yet prove silicon-faithful data movement because the current Renode model does not expose the BE-U1000 DMA engine.
- `E11` extends the focused migration proof to I2S transmitter configuration and sample-write semantics with bounded FIFO fill/drain, explicit flush behavior, and latched overrun observation, but it does not yet prove full codec interaction, DMA audio streaming, or silicon-faithful audio timing.
- `E12` extends the focused migration proof to PWMA timebase semantics with clearer update-flag lifecycle observation and live repetition-counter reprogramming, but it does not yet prove advanced channel behavior, real interrupt delivery, or output waveform timing on silicon.
- `E13` extends the focused migration proof to USB controller register/config semantics plus `cfg=0x9e` / `power=0x60` observation, rotating indexed `INTRTX` snapshots, EP0 `CSR0/COUNT0` readiness, and `idx=2` `RXCSR/RXCOUNT` packet-ready/count-style observation, but it does not yet prove actual enumeration, endpoint traffic, or TinyUSB-class behavior.
- `S1` through `S5` remain historical notes because they relied on approximate Renode SMP probing and are not part of the declared supported matrix or maintained pixi task surface.
- Core2 remains reserved/helper only; no current stage promotes it into generic SMP.
- `boards/be_u1000/board_config.h` owns immutable BE-U1000 facts, while the top-level build selects the active lane policy exposed through `OS_CFG_*` values.
- Promotion of any later stage requires the support registry, command surface, and blocking CI to be updated in the same change.

## Remaining unresolved items

- Real-silicon validation is still unresolved.
- The current scheduler-balancing proof is a smoke check based on an unpinned task being observed on both SMP cores, not a full migration or throughput benchmark.
- Any promotion from experimental to supported requires updating `docs/SUPPORTED_MATRIX.md` and the acceptance workflow in the same change.
