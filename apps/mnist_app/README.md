# MNIST App

`apps/mnist_app` is the canonical supported AI application in `rrtos`.

## What it contains

- `src/main.c` - simple runtime loop example
- `src/validation_main.c` - supported runtime validation entrypoint
- `src/quant_validation_main.c` - ST MNISTv1 INT8 runtime validation entrypoint
- `src/miniresnet_validation_main.c` - experimental STM32AI MiniResNet runtime measurement entrypoint
- `src/validation.c` - shared validation helpers
- `src/mnist_validation_samples.h` - committed five-sample MNIST batch used by runtime regression
- `generated/` - generated model wrappers and descriptors
- `generated_quant/` - separated generated wrappers for the quantized ST MNISTv1 model
- `generated_miniresnet/` - separated generated wrappers for the STM32AI MiniResNet sweep candidate

## Build

```bash
pixi run -e rv32 configure
pixi run -e rv32 build
```

## Canonical validation

Run the supported QEMU gate:

```bash
pixi run -e rv32 validate-mnist-runtime
```

Run the quantized ST MNISTv1 QEMU lane:

```bash
pixi run -e rv32 validate-mnist-quant-runtime
```

Run the optional Renode observation lane:

```bash
pixi run -e rv32 observe-mnist-runtime-renode
pixi run -e rv32 compare-mnist-runtime-platforms
```

The maintained AI task surface intentionally stays small: `validate-supported-ai`, `validate-mnist-runtime`, `validate-mnist-quant-runtime`, `observe-mnist-runtime-renode`, and `compare-mnist-runtime-platforms`.

Run the experimental STM32AI MiniResNet measurement lane directly:

```bash
python3 scripts/run_miniresnet_validation.py \
  --kernel build/apps/mnist_app/miniresnet_validation \
  --log logs/miniresnet_validation_qemu.log
```

## Validation behavior

The validation target:

- initializes the canonical registry runtime
- loads `st_mnist_28` through the public registry lookup path
- verifies tensor metadata through the registry contract before inference
- runs a five-sample batch from the official MNIST `t10k` test set
- normalizes the committed pixel bytes to the model's expected input range
- fails when any sample argmax differs from the dataset label

The quantized validation target loads `st_mnistv1_28_tfs_int8` from `generated_quant/`, runs the first committed MNIST sample through the ST MNISTv1 INT8 model, and checks the digit-7 argmax against the historical quantized-model behavior.

The experimental MiniResNet target loads `miniresnetv1_s1_64x50_tl_int8`
from `generated_miniresnet/`, feeds a deterministic synthetic int8 input
pattern, and records image size, heap peak, cycle count, and instruction count.
It intentionally does not assert ESC10 classification accuracy because the
project does not carry the corresponding audio preprocessing and fixture set.

Runtime logs include `latency_us`, `latency_cycles`, and
`latency_instructions`. The QEMU runners use `-icount shift=0,align=off,sleep=off`
so the timing counters advance from guest execution instead of host wall-clock
speed. `latency_us` still comes from CLINT `mtime`; use `latency_instructions`
for simulator-side relative comparison, and treat `latency_cycles` converted
with `OS_CFG_CPU_FREQ_HZ` as a rough target-time estimate until silicon
measurements exist.

The supported proof path uses `ai_model_find_by_name()`, `ai_model_get_input_info()`, `ai_model_get_output_info()`, and `ai_infer_sync()` directly in `src/validation_main.c`. Generated wrappers such as `ai_st_mnist_28_run()` remain convenience/example glue.

The sample fixture is generated by `scripts/generate_mnist_validation_samples.py` and stored in `src/mnist_validation_samples.h` so CI does not need network access.

## Code requirements

- `ai_models.yaml` declares the canonical FP32 model, `st_mnist_28`.
- `ai_models_mnist_quant.yaml` declares the separated ST MNISTv1 INT8 model, `st_mnistv1_28_tfs_int8`.
- `ai_models_stm32ai_miniresnet.yaml` declares the experimental STM32AI MiniResNet model, `miniresnetv1_s1_64x50_tl_int8`.
- Supported FP32 generated code lives in `generated/`; quantized generated code lives in `generated_quant/`; experimental MiniResNet generated code lives in `generated_miniresnet/` so each firmware links one registry.
- Any new supported model must include a registry descriptor, generated artifacts, validation samples or another deterministic runtime gate, and matching pixi/documentation updates.
- Do not solve model ABI differences by patching `third_party/iree`; keep integration glue in project-owned code.
